# Security and native-build review — 2026-09-28

## Credentials and local data

A public RevenueCat Test Store SDK key is present in ignored `.env.local` and absent from tracked source. Its value was not printed during this review. `EXPO_PUBLIC_` values are bundled into the client and are not a secret store. The app accepts only a `test_` key in a development build; a secret RevenueCat REST key must never be used. `.env` variants are ignored, while `.env.example` documents the variable. Source search found no logging of answer scripts or API keys. Development builds set the SDK's DEBUG log level without logging the key directly; release builds do not configure the Test Store. Existing speech code logs only platform/locale/on-device capability in development.

Answers and presentations are stored in AsyncStorage. They are not encrypted, cloud-synced, or restored by RevenueCat. Deleting the app can delete them. The `@promptside/app-data/v1` key is read and copied to `@cueback/app-data/v1` only inside the same app sandbox; the old value is retained. An older installation using `com.promptside.app` has a different iOS sandbox from current `com.cueback.app` and needs explicit data export/migration after device inspection.

## Dependency review

Installed: Expo 55.0.31, React Native 0.83.10, `react-native-purchases` 10.10.1, `expo-dev-client` 55.0.40. The unused `react-native-purchases-ui` package was removed because Cueback uses its own SDK-backed Pro screen. CocoaPods autolinking now includes `RNPurchases` and excludes `RNPaywalls`. `npm explain fsevents` traces it to optional `jest-haste-map`/Babel-Jest tooling pulled by React Native. `npm explain unrs-resolver` traces it to `eslint-import-resolver-typescript` through `eslint-config-expo`, a development-only tool. These install-script warnings do not by themselves establish runtime vulnerabilities.

An online `npm audit --json` on September 28 reported **13 moderate** advisories, with no high or critical advisories. Affected paths include Expo CLI/config/build tooling, `xcode` → `uuid`, and `@react-navigation/core` → `query-string` → `decode-uri-component`. The direct `expo` package has no compatible automatic fix in this lockfile; `react-native-executorch-expo-resource-fetcher` inherits that Expo advisory. The `decode-uri-component` advisory concerns denial of service on malformed percent-encoded input and is on a navigation dependency path, so malformed links should be treated as a possible runtime exposure until a compatible update is validated. The `uuid` issue is on the `xcode` build-tool path. No forced update was applied: Expo 55 and native module compatibility must be retained. Reassess these advisories before publication. Do not run `npm audit fix --force`.

## Native build review

Xcode 27.0 and CocoaPods 1.17.0 are installed. CoreSimulatorService responded when run with host permissions and listed an iOS 26.5 runtime with iPad and iPhone devices. `pod install --no-repo-update` succeeded and installed `RNPurchases` 10.10.1, `PurchasesHybridCommon` 19.2.0, and RevenueCat 5.90.1. The Simulator.app GUI is absent from this Xcode installation, so `expo run:ios --device <iPad UDID>` stopped before compiling with “Can't determine id of Simulator app.” A headless `xcodebuild` attempt reached the Pods project but Xcode 27 rejected several Pod targets set to iOS 13.x. A second attempt set `IPHONEOS_DEPLOYMENT_TARGET=17.0` for that command only and compiled the pods, including RevenueCat, but failed linking the Cueback app with unresolved React Native/Expo symbols (`RCTPackagerConnection`, `RCTReconnectingWebSocket`, and Fabric symbols) and missing Xcode frameworks (`CoreAudioTypes`, `UIUtilities`). **Native compile: FAIL; simulator launch and real SDK behavior: NOT TESTED.** This does not prove that the RevenueCat integration itself has a compile error.

`npx expo export --platform ios --output-dir /private/tmp/cueback-ios-export` successfully produced an iOS Hermes JavaScript bundle. The export log did not contain the API key value. This verifies JavaScript bundling, not native compilation or app launch. The temporary bundle includes public `EXPO_PUBLIC_` configuration by design; do not publish that build as a production payment app.

After installing Simulator.app (or repairing Xcode), run `npx expo run:ios --device "<simulator name or UDID>"`; the local ignored `.env.local` is loaded by Expo CLI. For a connected iPad, run `npx expo run:ios --device` with the current bundle ID and team. The `ios-simulator` EAS profile is configured for a development client and `ios.simulator: true`; a remote EAS builder **does not receive** `.env.local`. Set the same public SDK key in the EAS project's `development` environment before a cloud build. EAS login, project association, build availability, and any cost need owner verification. Do not claim native purchase operation until the app runs and the Test Store outcomes are observed.
